# Lesson 14 — S3 (Simple Storage Service)

## 1) What it is

**S3** is object storage.

You store objects (files) in **buckets**.

Examples:

- images
- backups
- logs
- reports

## 2) Why it’s needed

You need durable, scalable storage that:

- can store huge amounts of data
- doesn’t require managing disks or servers

## 3) Where it fits

In AcmeShop:

- product images go to S3
- generated reports can be stored in S3

S3 is not the database; it’s file/object storage.

## 4) How it works

- Bucket is a container
- Object has a key (path-like name)
- Access controlled by IAM policies and bucket policies

## 5) Connections

- IAM roles allow EC2/EKS workloads to read/write S3
- CloudWatch can monitor some activity (basic metrics)
- Applications often store static assets in S3

## 6) Real-world example

AcmeShop uploads `images/sku-123.jpg` to bucket `acmeshop-assets`.

The app stores the S3 key in RDS, and when users browse, the app returns image URLs.

## 7) Common mistakes

- Making buckets public by accident
- Putting secrets into S3 without encryption/controls
- Confusing S3 with a filesystem (it’s object storage)

## 8) Interview explanation

"S3 is highly durable object storage. I use it for static assets, backups, and reports. Access is controlled via IAM and bucket policies, and I keep buckets private by default unless intentionally serving public content through controlled mechanisms."

## Summary

- S3 stores objects in buckets
- Great for assets, backups, reports
